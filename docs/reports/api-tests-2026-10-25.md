## Scénarios API observés

- Profils, association en attente puis activation plateforme, attribution staff, interdiction de configurer comme staff, protection du dernier administrateur et révocation effective avec le même token.
- Isolation entre donateurs et associations ; lecture authentifiée du contenu photo ; rejet d'un fichier non image, d'une quatrième photo, d'un fichier dépassant 5 MiB et d'une image dépassant 20 mégapixels.
- Analyse simulée, correction humaine, comparaison des originaux indépendamment de l'ordre de retour des indicateurs et rejet d'une révision obsolète.
- Publication, matching par coordonnées/adresse, offre, décision exclusivement staff, réservation, rejeu idempotent et conflit de clé avec corps différent.
- QR signé, résolution, rejet d'un QR falsifié, réception dans la fenêtre réelle, absence de doublon sur rejeu, inventaire, galerie, comptes de dates, distribution et refus d'une seconde distribution.
- Refus puis nouvelle offre sur la même donation, retrait/restauration, annulation de réservation, pagination et réconciliation.
- Dates via API : hier, aujourd'hui, 1/6/7/29/30/89/90/91 jours ; date absente/illisible ; non applicable ; DDM/DLC partielle ; PAO non ouvert et ouverture manquante.

La suite pytest complète apporte aussi ses régressions déterministes pour matching/FEFO, limites calendaires, correction auditée sans contournement d'une date stricte, originaux tardifs, historique/périmètre figé et concurrence sur stockage/place/quota. Les expirations longues et les courses ne sont pas prétendues observées par le seul script curl séquentiel.

## Anomalies et limites

**Aucun échec pendant cette campagne.** Un avertissement de dépréciation Starlette/AnyIO est remonté dans TestClient ; il n'a pas fait échouer les tests. La couverture de branches reste à 76,23 % : le score combiné n'est pas une preuve d'exhaustivité.

Les deux groupes non exécutés par le script principal concernent les longues échéances/courses/cas temporels contrôlés et l'évaluation visuelle sur photos réelles. Une partie des premiers est couverte séparément par pytest ; l'évaluation visuelle ne l'est pas.

## Essais réels bloqués ou restant à faire

À l'inspection de l'environnement du terminal, DONOR_TOKEN, OTHER_DONOR_TOKEN, ADMIN_TOKEN, STAFF_TOKEN, OTHER_ADMIN_TOKEN, PLATFORM_TOKEN et PHOTO étaient absents. L'existence d'un backend/.env ne fournit pas ces sessions utilisateurs ni une photo annotée. Aucun token n'a été inventé pour les services hébergés.

| Validation | Statut / prérequis |
|---|---|
| API contre le projet Supabase configuré | **Bloquée** pour cette campagne : fournir les six sessions de test et une photo de vêtement, identifier le projet comme développement dédié et vérifier que ses migrations sont appliquées. |
| Google OAuth et tokens réels | **Non exécutée** ; obtenir les sessions via le fournisseur configuré. |
| Modèle OpenAI réellement sélectionné | **Non exécutée** ; après préparation précédente, activer RUN_OPENAI=1 sur le serveur réellement configuré. |
| Qualité des cinq catégories, médicaments/para/aliments froids | **Non exécutée** ; fournir et annoter 25–35 photos, puis revue humaine des résultats. |
| BAN réel dans cette campagne | **Non exécutée** ; le scénario adresse devra être rejoué sur l'instance configurée. |
| RLS/grants/ownership du Supabase hébergé | **Non exécutée** ; les succès PostgreSQL locaux ne prouvent pas la configuration distante. |
| Déploiement, sauvegarde/restauration, HTTPS/CORS, charge/coûts | **Hors de cette exécution**, à valider sur la cible. |

## Commandes exécutées

Depuis backend/ :

```sh
.venv/bin/ruff check .
.venv/bin/mypy app
.venv/bin/pytest -q -s --tb=short --cov=app \
  --cov-report=json:/tmp/dono-execution-coverage.json \
  --junitxml=../docs/reports/api-tests-2026-10-25.xml
```

Depuis la racine :

```sh
bash -n backend/scripts/test-api.sh
bash -n backend/scripts/test-api-expiry.sh
```

Pour rejouer contre les services réels, suivre [les variables et commandes curl](../api-curl-tests.md). Ne pas partager les tokens ou le .env dans le rapport ; les renseigner dans le terminal avec la saisie masquée prévue par le guide.
